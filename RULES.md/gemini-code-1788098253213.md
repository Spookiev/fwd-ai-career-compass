# RULES.md — Engineering Standards, AI Guardrails & Constraints

## Inviolable Product & AI Guardrails
- NEVER reject or gatekeep a student because they are a beginner or lack technical artifacts.
- NEVER treat a resume as absolute ground truth; assign confidence levels (Claimed vs. Evidenced).
- NEVER recommend a career trajectory based on a single aptitude or coding test.
- NEVER force every student down a software engineering/coding path. Support Tech, Hybrid, Product, Creative, and Non-Tech roles natively.
- NEVER tell a student they are "not capable" of a field; frame feedback around current evidence and missing competencies.
- NEVER punish slow learners or frame lower pacing as failure. Automatically adapt roadmaps without penalty.
- NEVER use salary benchmarks as the primary recommendation filter; prioritize intrinsic interest, capability fit, and realistic growth.
- NEVER claim clinical or psychological diagnosis from mood/energy check-ins. Keep wellbeing guidance strictly focused on sustainable academic pacing and break suggestions.
- NEVER present a single opaque "AI Score". Always break readiness down into discrete dimensions (Fit, Skills, Presence, Interview, Consistency).

## 1. Strict What-to-Use vs. What-to-Avoid

| Category | Allowed / Mandatory | Strictly Forbidden |
| :--- | :--- | :--- |
| **Styling** | Tailwind CSS utility classes, custom CSS variables for themes | Inline style tags, ad-hoc heavy UI component libraries |
| **State Management** | React Context (`AuthContext`, `ThemeContext`), custom hooks | Uncontrolled global prop-drilling, Redux overhead for simple tabs |
| **Icons** | `lucide-react` | FontAwesome, material web fonts, unoptimized SVGs |
| **Charts** | `recharts` with responsive containers | Chart.js, raw HTML tables for visual data |
| **PDF Extraction** | Client-side `pdfjs-dist` | Server-heavy unverified binary upload parsers |
| **Terminology** | Tier Progression, Milestone Verification, Readiness Index | "Gamified", "XP", "Boss Fights", "Loot" (keep professional/academic) |

## 2. AI Prompting & Output Boundaries
- **Strict Structured Outputs:** All Gemini prompts must enforce structured JSON output adhering to TypeScript schemas.
- **Explainability Requirement (PSAIAC_36):** The AI must never recommend a career without providing an explicit, evidence-based rationale citing the student's actual inputs (e.g., aptitude score, coursework, or project history).
- **Safety & Zero Hallucination:** OER recommendations must target verified platforms (NPTEL, SWAYAM, Coursera Audit, YouTube channels).
- **No Mock Stubs in Production:** When Gemini API keys are active, dynamic prompts must execute live; fallback to mock data only on catch-block error handling.

## 3. Security & Error Handling Standards
- **Client Key Isolation:** Never expose backend admin credentials to the frontend.
- **Graceful Degradation:** If PDF parsing fails on corrupt files, provide immediate inline fallback to manual text entry.
- **Firestore Access Isolation:** Faculty private notes must be explicitly excluded from client-side student queries using Firestore security rules.
